# 리치마작 점수 계산기 구현 명세

## 1. 목표

손패와 화료 상황을 입력받아 **판수 · 부수 · 최종 점수**를 산출하는 계산기를 만든다.
일본 리치마작(텐호 표준 룰) 기준.

---

## 2. 패 표기법

내부 표현은 문자열 코드로 통일한다.

| 종류 | 코드 | 범위 |
|---|---|---|
| 만수패 | `1m` ~ `9m` | 9종 |
| 통수패 | `1p` ~ `9p` | 9종 |
| 삭수패 | `1s` ~ `9s` | 9종 |
| 자패 | `1z` ~ `7z` | 東南西北白發中 순서 |

- 총 34종, 각 4장 = 136장
- 자패 매핑: `1z`=東, `2z`=南, `3z`=西, `4z`=北, `5z`=白, `6z`=發, `7z`=中
- 요구패(幺九牌) = 1·9 수패 + 모든 자패
- 노두패(老頭牌) = 1·9 수패만
- 중장패(中張牌) = 2~8 수패

UI 표시는 "1만 / 5통 / 9삭 / 東" 형태로 변환한다.

## 3. 입력 데이터 모델

```typescript
interface WinInput {
  // 손패 (부로 제외한 감춰진 패). 화료패 제외.
  concealed: string[];

  // 부로한 면자 목록
  melds: Meld[];

  // 화료패
  winningTile: string;

  // 화료 방식
  isTsumo: boolean;

  // 장풍 / 자풍
  roundWind: '1z' | '2z' | '3z' | '4z';
  seatWind: '1z' | '2z' | '3z' | '4z';

  // 리치 관련
  riichi: boolean;
  doubleRiichi: boolean;
  ippatsu: boolean;

  // 특수 화료 상황
  haitei: boolean;      // 해저로월 (마지막 패 쯔모)
  houtei: boolean;      // 하저로어 (마지막 버림패 론)
  rinshan: boolean;     // 영상개화 (깡 후 쯔모)
  chankan: boolean;     // 창깡 (가깡 패를 론)
  tenhou: boolean;      // 천화 (친 배패 화료)
  chiihou: boolean;     // 지화 (자 첫 쯔모 화료)

  // 도라
  doraIndicators: string[];
  uraDoraIndicators: string[];

  // 적도라 개수 (0-4, 룰 옵션)
  akaDora: number;

  // 공탁/적봉 (선택)
  honba: number;        // 본장
  riichiSticks: number; // 리치봉
}

interface Meld {
  type: 'chi' | 'pon' | 'ankan' | 'minkan';
  tiles: string[];
}
```

**주의**: `ankan`(안깡)은 멘젠을 깨지 않는다. `chi`/`pon`/`minkan`만 멘젠을 깬다.

## 4. 처리 파이프라인

```
입력 검증
  ↓
손패 분해 (모든 가능한 분해 열거)
  ↓
분해별로 { 역 판정 → 판수 계산 → 부수 계산 } 반복
  ↓
최고 점수가 나오는 분해 선택
  ↓
점수 산출 (지불 내역 포함)
```

**핵심**: 한 손패가 여러 방식으로 분해될 수 있다.
예) `1112345678999p` + `5p` 는 분해 방법이 여러 가지이고,
분해에 따라 성립하는 역과 부수가 달라진다.
**모든 분해를 계산해 최대 점수를 채택**해야 한다.

## 5. 손패 분해 알고리즘

### 5.1 검증

- 부로 포함 총 14장인가 (깡은 4장이지만 면자 1개로 계산 → 깡 1개당 총장수 +1)
- 같은 패가 5장 이상 없는가
- 화료패가 손패에 실제로 붙는가

### 5.2 일반형 분해

머리 1개(2장) + 면자 4개(각 3장) 구조.

```
for 각 패 종류 t (34종):
    if count[t] >= 2:
        머리로 t 2장 제거
        재귀적으로 면자 4개 추출 시도 (백트래킹)
            - 커쯔: count[t] >= 3 이면 3장 제거
            - 슌쯔: 수패이고 t, t+1, t+2 각 1장 이상이면 제거
        성공하면 분해 결과에 추가
```

부로한 면자는 이미 확정이므로 분해 대상에서 제외하고, 결과에 그대로 합친다.

### 5.3 특수형

일반형 분해와 **별개로** 검사한다.

- **치토이츠**: 서로 다른 7종이 각 2장씩. (같은 패 4장을 2쌍으로 세는 것은 불가)
- **국사무쌍**: 13종 요구패가 모두 있고, 그중 하나가 2장.

## 6. 역 판정

### 6.1 역만 (성립 시 일반 역과 합산하지 않음)

| 역 | 조건 | 배수 |
|---|---|---|
| 천화 | 친이 배패 상태로 화료 | 1 |
| 지화 | 자가 첫 쯔모로 화료 (그 전에 부로 없음) | 1 |
| 국사무쌍 | 13종 요구패 + 그중 1장 중복 | 1 |
| 국사무쌍 13면 | 텐파이 시 13종 각 1장 (13면 대기) | 2 |
| 사안커 | 안커 4개 | 1 |
| 사안커 단기 | 안커 4개 + 머리 단기 대기 | 2 |
| 대삼원 | 白發中 모두 커쯔 | 1 |
| 소사희 | 풍패 3종 커쯔 + 1종 머리 | 1 |
| 대사희 | 풍패 4종 모두 커쯔 | 2 |
| 자일색 | 14장 전부 자패 | 1 |
| 녹일색 | 2s·3s·4s·6s·8s·發 만으로 구성 | 1 |
| 청노두 | 14장 전부 노두패(1·9 수패) | 1 |
| 구련보등 | 한 색으로 1112345678999 + 1장 | 1 |
| 순정구련보등 | 텐파이 시 13장이 정확히 1112345678999 | 2 |
| 사깡즈 | 깡 4개 | 1 |

**사안커 판정 주의**: 커쯔의 3장째를 **론**으로 완성하면 명각 취급이라 안커가 아니다.
쯔모로 완성하면 안커. 단, 머리 단기 대기로 론한 경우는 나머지 4개가 이미 안커이므로 성립.

### 6.2 일반 역

멘젠 전용 역은 `M`, 판내림 있는 역은 `멘젠판/부로판`으로 표기.

| 역 | 판 | 조건 |
|---|---|---|
| 리치 | 1 (M) | 리치 선언 |
| 더블리치 | 2 (M) | 첫 순목 리치 |
| 일발 | 1 (M) | 리치 후 1순 내 화료, 중간에 부로 없음 |
| 멘젠쯔모 | 1 (M) | 멘젠 + 쯔모 |
| 핑후 | 1 (M) | 면자 4개 전부 슌쯔 + 머리가 역패 아님 + 양면 대기 |
| 이페코 | 1 (M) | 동일 슌쯔 2개 |
| 량페코 | 3 (M) | 동일 슌쯔 2쌍 (이페코와 중복 불가) |
| 탄야오 | 1 | 14장 전부 중장패(2~8) |
| 역패 | 1씩 | 장풍 커쯔 / 자풍 커쯔 / 삼원패 커쯔 (각각 1판, 중복 가산) |
| 치토이츠 | 2 (M) | 7쌍 |
| 토이토이 | 2 | 면자 4개 전부 커쯔 |
| 삼안커 | 2 | 안커 3개 |
| 삼색동각 | 2 | 만·통·삭 같은 숫자 커쯔 각 1개 |
| 삼깡즈 | 2 | 깡 3개 |
| 혼노두 | 2 | 14장 전부 요구패 (커쯔 구성) |
| 소삼원 | 2 | 삼원패 2종 커쯔 + 1종 머리 |
| 삼색동순 | 2/1 | 만·통·삭 같은 숫자 슌쯔 각 1개 |
| 일기통관 | 2/1 | 한 색으로 123·456·789 |
| 찬타 | 2/1 | 모든 면자와 머리에 요구패 포함 |
| 준찬타 | 3/2 | 모든 면자와 머리에 노두패 포함 (자패 불가) |
| 혼일색 | 3/2 | 한 색 수패 + 자패 |
| 청일색 | 6/5 | 한 색 수패만 |
| 해저로월 | 1 | 마지막 패로 쯔모 |
| 하저로어 | 1 | 마지막 버림패로 론 |
| 영상개화 | 1 | 깡 후 링샹패로 쯔모 |
| 창깡 | 1 | 가깡한 패를 론 |

### 6.3 상위 역 흡수 규칙

성립 시 하위 역을 **제외**한다.

- 준찬타 성립 → 찬타 제외
- 혼노두 성립 → 찬타 제외
- 청일색 성립 → 혼일색 제외
- 량페코 성립 → 이페코 제외
- 치토이츠 → 이페코·량페코·핑후·토이토이 불가
- 역만 성립 → 모든 일반 역 무시

### 6.4 역 없음 판정

도라·우라도라·적도라는 **역이 아니다.**
역이 하나도 없으면 화료 불가로 처리한다. (에러 반환)

## 7. 부수 계산

### 7.1 가산 항목

| 항목 | 부 |
|---|---|
| 기본 부(부저) | 20 |
| 멘젠 론 | +10 |
| 쯔모 | +2 |

**면자**

| | 중장패 | 요구패 |
|---|---|---|
| 명각 | 2 | 4 |
| 안커 | 4 | 8 |
| 명깡 | 8 | 16 |
| 안깡 | 16 | 32 |

**머리**

| 종류 | 부 |
|---|---|
| 역패(장풍/자풍/삼원패) | 2 |
| 연풍패(장풍 = 자풍) | 2 (룰 옵션: 4) |
| 그 외 | 0 |

**대기**

| 형태 | 부 |
|---|---|
| 양면 | 0 |
| 샤보 | 0 |
| 칸찬 | 2 |
| 펜찬 | 2 |
| 단기 | 2 |

계산 후 **10 단위 올림**.

### 7.2 예외 규칙 (반드시 구현)

| 상황 | 부수 |
|---|---|
| 핑후 쯔모 | **20부 고정** (쯔모 2부 붙이지 않음) |
| 핑후 론 | **30부 고정** (20 + 멘젠론 10) |
| 치토이츠 | **25부 고정** (올림 없음, 멘젠론 10부 없음) |
| 부로 + 부수 0 + 론 (쿠이핑후형) | **30부** |

즉 20부는 핑후 쯔모에서만 나온다.

### 7.3 커쯔 판정

화료패로 완성된 커쯔는 **쯔모면 안커, 론이면 명각**으로 처리한다.
부수와 사안커 판정 모두에 영향을 준다.

## 8. 도라 계산

표시패 → 도라 변환은 **순환**한다.

| 표시패 | 도라 |
|---|---|
| 1m~8m | 다음 숫자 |
| 9m | 1m |
| 東→南→西→北→東 | 풍패 순환 |
| 白→發→中→白 | 삼원패 순환 |

- 도라: 항상 적용
- 우라도라: **리치 화료 시에만** 적용
- 적도라: 별도 카운트
- 부로한 패, 안깡한 패, 화료패 모두 도라 카운트 대상

## 9. 점수 산출

### 9.1 기본점

```
기본점 = 부수 × 2^(2 + 판수)
```

기본점이 **2000을 초과하면 2000으로 절삭**(= 만관 처리).

### 9.2 판수 구간 (만관 이상)

| 구간 | 판수 | 기본점 |
|---|---|---|
| 만관 | 5판, 또는 기본점 2000 초과 | 2000 |
| 하네만 | 6~7판 | 3000 |
| 배만 | 8~10판 | 4000 |
| 삼배만 | 11~12판 | 6000 |
| 역만 | 13판 이상 또는 역만 역 | 8000 |
| 더블역만 | 역만 2배 | 16000 |

**역만은 판수로 환산하지 않고 별도 처리**한다. (13판 누적 = 카조에역만은 룰 옵션)

### 9.3 지불 계산

```
친 론      = 기본점 × 6
자 론      = 기본점 × 4
친 쯔모    = 기본점 × 2 × 3명  (= "N올")
자 쯔모    = 친에게 기본점 × 2, 자에게 기본점 × 1
```

모든 지불액은 **100점 단위 올림**.

### 9.4 본장·리치봉

```
론  : 방총자가 추가로 (본장 × 300) 지불
쯔모: 각자 추가로 (본장 × 100) 지불
리치봉: 화료자가 전부 수령
```

## 12. 테스트 케이스

구현 검증용. 모두 실제 계산 결과다.

### 기본

```
[1] 자가 / 東장 / 南가 / 리치 / 멘젠
    손패: 1m1m1m 456p 789p 中中中 5s
    화료: 5s 론
    → 2판 50부 3200점
    (리치1 + 中1 / 부저20 + 멘젠론10 + 1m안커8 + 中안커8 + 단기2 = 48 → 50부)

[2] 자가 / 東장 / 南가 / 멘젠 / 도라표시 2p
    손패: 234m 345p 678p 34s 5s5s
    화료: 2s 쯔모
    → 3판 20부 700/1300
    (핑후1 + 쯔모1 + 도라1 / 핑후 쯔모 20부 고정)

[3] 자가 / 부로 白폰 / 도라표시 1s
    손패: 234m 567p 9s9s 3s4s + 白白白(폰)
    화료: 5s 론
    → 1판 30부 1000점
```

### 부수 예외

```
[4] 부로 + 무부수 + 론 (쿠이핑후형)
    자가 / 부로 2s3s4s치 / 도라표시 6p
    손패: 345m 678p 5m5m 7s8s + 234s(치)
    화료: 6s 론
    → 2판 30부 2000점  ※ 20부가 아니라 30부

[5] 치토이츠
    자가 / 리치 / 25부 고정
    손패: 1m1m 5m5m 9m9m 3p3p 7p7p 2s2s 6s
    화료: 6s 론
    → 3판 25부 3200점
```

### 만관 경계

```
[6] 친 / 4판 30부 → 기본점 1920 (만관 아님)
    → 11600점

[7] 친 / 4판 40부 → 기본점 2560 (만관 처리)
    → 12000점

[8] 자 / 4판 30부 → 7700점
[9] 자 / 4판 40부 → 8000점 (만관)
```

### 더블 역패

```
[10] 친 / 東장 / 東가 / 東東東 커쯔
     → 역패 東 2판 (장풍 + 자풍 각 1판)
```

### 복합 역

```
[11] 혼노두 성립 손패는 반드시 토이토이도 성립
     손패: 111m 999m 111p 999p 東東
     → 혼노두2 + 토이토이2 + 삼안커2 (론) 또는 사안커(쯔모, 역만)

[12] 일기통관 + 청일색 동시 성립
     손패: 123m 456m 789m 234m 55m
     → 청일색6 + 일기통관2 + 핑후1 = 9판 배만
```

### 역만

```
[13] 사안커 (쯔모)
     손패: 111m 999m 111p 999s 東 / 東 쯔모 → 사안커 역만

[14] 사안커 단기 (론)
     손패: 111s 999s 111m 999p 南 / 南 론 → 사안커 단기 더블역만

[15] 국사무쌍 13면
     손패: 1m9m 1p9p 1s9s 東南西北 白發中 / 아무 요구패 → 더블역만

[16] 순정구련보등
     손패: 1112345678999p / 아무 통수패 → 더블역만

[17] 녹일색
     허용패: 2s 3s 4s 6s 8s 發 만

[18] 자일색 + 소사희 중첩 → 더블역만
     손패: 東東東 南南南 西西西 中中中 北北
```

### 역 없음

```
[19] 부로 + 역패 없음 + 탄야오 불가
```

# 2단계: 퀴즈 모드 (엔진 완성 후)

계산기가 동작하면 같은 엔진으로 퀴즈를 만든다. **서버는 여전히 불필요하다.**

## 16. 문제 생성

### 16.1 원리

정답 데이터를 미리 만들어 저장하지 않는다.
`calculateScore()`가 손패를 넣으면 정답을 돌려주는 함수이므로,
**랜덤 손패를 만들어 그 함수에 넣으면 그게 곧 정답**이다.

```javascript
function generateProblem(condition) {
  for (let i = 0; i < MAX_ATTEMPTS; i++) {
    const hand = condition.template
      ? generateByTemplate(condition.template)  // 역 지정 → 역산 생성
      : randomWinningHand();                    // 지정 없음 → 완전 랜덤

    const situation = randomSituation();
    const answer = calculateScore(hand, situation);

    if (!answer.valid) continue;                       // 역 없음 → 폐기
    if (!matchesCondition(answer, condition)) continue; // 조건 불일치 → 폐기

    return { hand, situation, answer };
  }
  throw new Error('조건에 맞는 문제를 생성하지 못했습니다');
}
```

`MAX_ATTEMPTS`(기본 1000)로 무한 루프를 막는다.

### 16.2 랜덤 완성형 생성

```
1. 34종 각 4장의 풀을 준비
2. 머리 1개 선택 (같은 패 2장)
3. 면자 4개 선택 (커쯔 또는 슌쯔), 풀 잔량 확인
4. 총 14장 완성
5. 그중 1장을 화료패로 분리 → 손패 13장
```

**같은 패 5장 이상이 나오지 않도록** 매 단계 잔량을 검사할 것.

### 16.3 역 지정 생성 (템플릿)

완전 랜덤은 특정 역이 나올 확률이 낮다.
자주 쓰는 역은 **정의를 그대로 생성 규칙으로** 구현한다.

| 역 | 생성 방법 | 난이도 |
|---|---|---|
| 역패 | 랜덤 자패 커쯔 1 + 랜덤 면자 3 + 머리 | 쉬움 |
| 탄야오 | 2~8 패로만 면자 4 + 머리 | 쉬움 |
| 토이토이 | 랜덤 커쯔 4 + 머리 | 쉬움 |
| 치토이츠 | 서로 다른 7종 각 2장 | 쉬움 |
| 삼색동각 | 같은 숫자 커쯔 만·통·삭 + 면자 1 + 머리 | 쉬움 |
| 삼색동순 | 같은 숫자 슌쯔 만·통·삭 + 면자 1 + 머리 | 쉬움 |
| 일기통관 | 한 색 123·456·789 + 면자 1 + 머리 | 쉬움 |
| 혼일색 | 한 색 수패 + 자패로만 구성 | 쉬움 |
| 청일색 | 한 색 수패로만 구성 | 쉬움 |
| 핑후 | 슌쯔 4 + 역패 아닌 머리, **화료패를 양면 위치로 강제** | 중간 |
| 이페코 | 동일 슌쯔 2개 + 면자 2 + 머리 (멘젠 강제) | 중간 |
| 사안커 | 커쯔 4 + 머리, **쯔모 강제** (또는 머리 단기 론) | 중간 |
| 찬타 | 면자를 123/789/111/999/자패커쯔 중에서만 선택 | 중간 |
| 준찬타 | 위에서 자패 제외 | 어려움 |
| 역만류 | 형태가 고정이므로 하드코딩이 가장 간단 | 쉬움 |

**핑후 생성 시 주의**: 슌쯔 4개를 만든 뒤 아무 패나 빼면 칸찬·펜찬이 되어 핑후가 깨진다.
`123`도 `789`도 아닌 슌쯔를 골라 그 양끝 중 하나를 화료패로 지정할 것.

**부로 문제 생성 시 주의**: 부로하면 멘젠 역이 전부 소멸한다.
**역패 커쯔를 먼저 심거나 탄야오를 강제**하지 않으면 무역 손패가 대량 생성된다.

### 16.4 생성 후 검증

템플릿으로 만든 손패도 **반드시 엔진에 넣어 확인**한다.
의도한 역이 결과에 포함되지 않으면 폐기하고 재생성.

## 17. 퀴즈 UI / 채점

### 17.1 출제 형식

이 명세의 원 사용자가 실제로 연습한 형식을 따른다.

```
- 장풍 / 자풍 (친·자 표시)
- 멘젠 여부, 리치 여부
- 도라 표시패 (리치면 우라도라 표시패도 함께)
- 손패 (부로는 우측에 "(부로)" 표기)
- 화료패 + 화료 방식 (론/쯔모, 일발이면 "일발 론" / "일발 쯔모")
```

**도라를 직접 알려주지 않는다.** 표시패만 제시하고 사용자가 판정하게 한다.
"도라 없음" 같은 표기도 쓰지 않는다.

### 17.2 답안 입력

세 가지를 각각 입력받는다.

| 항목 | 입력 방식 |
|---|---|
| 판수 | 숫자 |
| 부수 | 숫자 (만관 이상이면 비활성화) |
| 점수 | 숫자, 쯔모면 자/친 지불액 2칸 또는 "올" 1칸 |

부수는 역만·만관 이상에서 계산이 무의미하므로 자동 비활성화한다.

### 17.3 채점 규칙

- **계산을 먼저 끝내고 정답/오답을 마지막에 표시**한다. 결과를 먼저 띄우고 번복하지 않는다.
- 판수·부수·점수를 **항목별로 부분 채점**한다. (부수는 맞고 점수만 틀린 경우가 흔함)
- 오답이면 `fuBreakdown`과 역 목록을 근거로 **어느 항목이 빠졌는지** 지목한다.

```
예) "토이토이 2판이 빠졌습니다.
     혼노두가 성립하면 몸통이 전부 커쯔일 수밖에 없으므로
     토이토이가 자동으로 붙습니다."
```

### 17.4 오답 패턴 추적

사용자가 반복해서 놓치는 항목을 누적 기록한다. localStorage로 충분.

```typescript
interface MistakeLog {
  missedYaku: Record<string, number>;   // 역별 누락 횟수
  fuErrors: Record<string, number>;     // 부수 항목별 오류 횟수
  scoreErrors: {
    ronTsumoConfusion: number;          // 론/쯔모 점수 혼동
    manganBoundary: number;             // 만관 경계 오판
    dealerConfusion: number;            // 친/자 혼동
  };
}
```

실제 관측된 대표적 오답 패턴 (출제 우선순위 근거로 활용):

- **멘젠쯔모 누락** — 부로 없이 쯔모면 자동 1판인데 빠뜨림
- **더블 東/南 누락** — 장풍과 자풍이 같으면 2판인데 1판으로 셈
- **토이토이 누락** — 혼노두를 발견하고도 토이토이를 빼먹음
- **청일색 누락** — 일기통관에 집중하다 색이 하나인 걸 놓침
- **핑후 누락** — 삼색동순 등 큰 역에 시선이 쏠려 핑후를 빠뜨림
- **명각/안커 혼동** — 자패 명각 4부를 안커 8부로 계산
- **론/쯔모 점수 혼동** — 쯔모인데 론 점수표를 봄, 또는 그 반대
- **만관 경계 오판** — 4판 30부(1920, 만관 아님)와 4판 40부(2560, 만관) 구분
- **탄야오 오판** — 슌쯔 안에 숨은 9를 놓침
- **화료패 도라 누락** — 화료패도 손패의 일부라는 점을 잊음

### 17.5 적응형 출제

`MistakeLog`를 읽어 자주 틀린 항목이 등장하는 문제의 출제 확률을 높인다.

```javascript
function pickTemplate(log) {
  const weights = Object.entries(log.missedYaku)
    .map(([yaku, count]) => ({ yaku, weight: 1 + count * 2 }));
  return weightedRandom(weights);
}
```

## 18. 3단계: AI 연동 (선택)

### 18.1 서버가 필요해지는 유일한 지점

**API 키를 프론트엔드에 둘 수 없다.** 브라우저 코드는 사용자가 전부 볼 수 있으므로
키가 노출되면 제3자가 사용자의 요금으로 API를 쓸 수 있다.

```
브라우저 → 서버리스 함수 (키 보관) → AI API
```

Vercel Functions / Cloudflare Workers로 **파일 하나면 충분**하다.
별도 백엔드 프로젝트는 불필요하고, 무료 티어로 감당된다.

### 18.2 AI에 맡길 것 / 맡기지 말 것

| 작업 | 담당 | 이유 |
|---|---|---|
| 문제 생성 | **엔진** | AI는 매수를 잘못 세거나 무역 손패를 만든다 |
| 정답 계산 | **엔진** | 결정론적이어야 하고 검증 가능해야 한다 |
| 채점 | **엔진** | 위와 동일 |
| 해설 문장 생성 | AI | 자연어 설명은 AI가 낫다 |
| 약점 분석·조언 | AI | 누적 로그를 읽고 패턴을 서술 |
| 학습 계획 제안 | AI | — |

**정답에 관한 모든 판단은 엔진이 한다.** AI는 이미 확정된 결과를 설명하는 역할만 맡는다.

### 18.3 프롬프트 설계

AI에는 **엔진이 계산한 결과를 함께 넘긴다.** AI가 다시 계산하게 하지 않는다.

```
[손패 정보]
[사용자 답안]
[엔진이 계산한 정답 + 역 목록 + 부수 내역]
[사용자의 누적 오답 패턴]

→ "위 정답은 확정된 값이다. 다시 계산하지 말고,
   사용자가 왜 틀렸는지 설명하라."
```
